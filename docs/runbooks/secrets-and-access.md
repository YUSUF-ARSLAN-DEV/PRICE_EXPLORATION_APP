# Secrets, rotation and access reviews (plan 8.2)

## Where secrets live
Generated by Terraform (random, stored in Key Vault, **also in Terraform state** - keep the state account private,
Entra-only, versioned): `jwt-secret`, `meili-master-key`, DB passwords (`db-password-api|worker|readonly`), connection
strings (`database-url-*`). Containers read them through managed identity + Key Vault references. Nothing is in git
(gitleaks runs in CI and pre-commit). Third-party secrets (email relay credentials, ACR import tokens) are added to
Key Vault by an admin - never to tfvars or pipelines.

## Rotation
| Secret | Cadence | Procedure |
| ------ | ------- | --------- |
| DB role passwords | 90 days / on suspicion | `terraform taint random_password.db_*` -> apply (updates Key Vault) -> run the **migrate** job (its `roles` step re-issues `ALTER ROLE ... PASSWORD`) -> restart api/jobs |
| JWT secret | 180 days / on suspicion | taint `random_password.jwt` -> apply -> restart api (all sessions end; users sign in again) |
| Meilisearch key | 180 days | taint -> apply -> restart meili + api + reindex job |
| Admin passwords | 90 days, MFA always | via the identity provider |
| TLS certificate | before expiry | import new PFX version into Key Vault (the gateway follows the versionless id) |
| GitHub OIDC | n/a | federated credentials have no secret; review subjects quarterly |

## Access (least privilege)
| Who | What | Through |
| --- | ---- | ------- |
| Engineers | read logs/metrics, deploy via pipeline | Entra groups; no standing production write access |
| Break-glass admin (2 people) | Owner on the production resource group | PIM/just-in-time, alert on activation |
| CI identity | contributor on the env resource group, Key Vault Secrets Officer (Terraform) | GitHub OIDC |
| Workloads | one managed identity each (api / web / worker) with only KV-read, ACR-pull, blob rights | Terraform |
| DB roles | `qarib_api`, `qarib_worker` (no personal data), `qarib_readonly` (public views) | migration 0011 |
| Admin console users | role=admin + SSO + MFA + IP allow-list; legal-status changes need a second admin | app + edge |
